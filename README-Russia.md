# aruaru-web

**Минимальный веб-интерфейс для aruaru-db (Rust → WebAssembly, без фреймворков)**

Табличная (вкладочная) панель, которая напрямую из браузера обращается к
запросам `sql` и `registrySummary` (сводка реестра поддерживаемых БД),
публикуемым `aruaru-db` (распределённой базой данных Git-on-SQL) через GraphQL
(`/graphql`), и отображает результаты. Помимо выполнения SQL-запросов и
сводки реестра, интерфейс включает вкладку **«Управление сайтами»**,
позволяющую регистрировать и переключать **несколько адресов подключения
(для aruaru-web и для других проектов)** — по аналогии со списком сайтов в
KUSANAGI.

## Что уже реализовано

- Отправляет настоящие GraphQL-запросы через `fetch()` на эндпоинт
  `/graphql` крейта `aruaru-graphql` (`aruaru-db/crates/aruaru-graphql`):
  - `sql(query: String!): QueryResultGql` — выполняет произвольный
    SQL-запрос и отображает `columns`/`rows`/`commandTag` в виде таблицы;
  - `registrySummary: RegistrySummaryGql` — отображает в виде карточек
    сводку по реестру поддерживаемых БД (более 150 записей);
  - `registry: [DbEntryGql!]!` — отображает **список** реестра
    поддерживаемых БД в виде таблицы (название/категория/совместимость по
    протоколу/статус/место в рейтинге/оценка/дата обновления).
- **Вкладка «Управление версиями»**: позволяет выполнять запросы
  `currentBranch`/`branches` (список веток и текущая ветка), `log(limit)`
  (журнал коммитов) и `diff(from, to)` (число добавленных/удалённых/
  изменённых элементов при сравнении веток). Все они основаны на реальной
  схеме `VcsQuery` из `aruaru-db/crates/aruaru-graphql`.
- Если `aruaru-server` не запущен или недоступен, интерфейс на месте
  отображает **пример данных точно в форме реальной схемы** и явно
  помечает его как «офлайн-образец» (это поведение проверено в реальном
  браузере — см. раздел «Проверка работоспособности» ниже).
- **Вкладка «Управление сайтами»**: позволяет регистрировать несколько
  адресов подключения (для aruaru-web и для других проектов) —
  IP-адрес/домен/поддомен/порт/путь — с сохранением в `localStorage` и
  переключением в один клик. Поле эндпоинта на вкладках SQL и реестра
  автоматически подстраивается под выбранный сайт. Для каждой карточки
  предусмотрена кнопка **«Проверка соединения»** (проверяет доступность
  без смены активного сайта), валидация порта (1–65535), **экспорт/импорт
  списка зарегистрированных сайтов в JSON** (для резервного копирования и
  переноса в другой браузер) и диалог подтверждения перед удалением.
- **Удобство вкладки SQL**: **история последних 10 запросов** (повторная
  загрузка по клику, полный текст при наведении), **сочетание клавиш
  Ctrl+Enter / Cmd+Enter** для запуска, **экспорт результатов в CSV**,
  отключение кнопки на время выполнения запроса, а также таблица
  результатов с отображением числа строк, прокруткой и закреплённым
  заголовком.
- **Автоматическая настройка, мониторинг и обновление HTTPS (TLS)**:
  `scripts/gen-vhost.sh` генерирует vhost для Nginx/Apache (с редиректом
  HTTP→HTTPS), `scripts/setup-tls.sh` получает сертификат Let's Encrypt
  (certbot), а `deploy/systemd/install-systemd-units.sh` включает
  «автообновление дважды в день» (`aruaru-tls-renew.timer`) и «мониторинг
  истечения раз в день» (`aruaru-tls-monitor.timer` →
  `scripts/check-all-tls.sh`). Подробности — в разделе «Регистрация HTTPS,
  домена/поддомена».

## Что пока не реализовано (честно о границах)

- GraphQL-мутации (создание веток, слияние, обход реестра и т. д.) не
  реализованы.
- Аутентификация, пагинация и автоматический повтор при ошибках не
  реализованы.
- Нативный опыт приложения, как у Tauri, не предоставляется (только WASM,
  работающий в браузере).
- **Фактическая покупка домена и регистрация DNS-записей (операции у
  регистратора) этим репозиторием не выполняются** (поскольку это связано
  с расходами и внешними сервисами). Автоматизировано здесь только
  «генерация конфигурации vhost» и «получение, мониторинг и автообновление
  TLS-сертификата» для уже приобретённого домена — саму регистрацию DNS
  пользователь выполняет у регистратора самостоятельно.

## Способ сборки

Node.js, npm и TypeScript не используются — всё делается только
средствами инструментальной цепочки Rust.

```bash
rustup target add wasm32-unknown-unknown        # только при первом запуске
cargo install wasm-bindgen-cli --version 0.2.126 # только при первом запуске (версия должна совпадать с Cargo.lock)

cargo build --target wasm32-unknown-unknown
wasm-bindgen --target web --no-typescript --out-dir pkg \
  target/wasm32-unknown-unknown/debug/aruaru_web.wasm

# раздайте статическим сервером и откройте (подойдёт любой, например:)
python -m http.server 8080
# откройте в браузере http://localhost:8080/index.html
```

При желании реально запустить `aruaru-db` и опробовать:

```bash
cd ../aruaru-db
cargo run -p aruaru-server -- --data ./data --raft-id 1   # GraphQL поднимется на :4000
```

## Запуск с указанного IP-адреса

```bash
scripts/serve.sh 0.0.0.0 8080        # слушать на всех интерфейсах
scripts/serve.sh 192.168.1.50 8080   # слушать только на указанном IP-адресе
```

## Регистрация HTTPS, домена/поддомена

Сам этот репозиторий не занимается покупкой домена или регистрацией
DNS-записей (эти операции у регистратора и связанные расходы пользователь
выполняет отдельно). Ниже описана локальная автоматизация для быстрого
выделения уже приобретённого домена/поддомена под aruaru-web или другие
проекты (аналог функции «Добавить сайт» в KUSANAGI).

```bash
# 1. Сгенерировать vhost (Nginx/Apache, с редиректом HTTP→HTTPS) из домена + IP + бэкенда
scripts/gen-vhost.sh aruaru.example.com 203.0.113.10 127.0.0.1:4000
# Поддомен для другого назначения — аналогично (достаточно изменить UPSTREAM/WEBROOT)
scripts/gen-vhost.sh tool.example.com 203.0.113.10 127.0.0.1:9000 /var/www/tool

# 2. Разместить сгенерированные файлы конфигурации и перезагрузить сервер (находятся в deploy/generated/, исключены через .gitignore)

# 3. Получить TLS-сертификат (Let's Encrypt / certbot)
scripts/setup-tls.sh aruaru.example.com admin@example.com /var/www/aruaru.example.com

# 4. Включить автообновление (дважды в день) + автомониторинг (раз в день, обнаружение скорого истечения)
sudo deploy/systemd/install-systemd-units.sh
```

Срок действия сертификатов всех зарегистрированных доменов можно в любой
момент проверить вручную с помощью `scripts/check-all-tls.sh`. Если
зарегистрировать те же адреса подключения и во вкладке «Управление
сайтами» графического интерфейса aruaru-web, переключение адресов в
браузере будет им соответствовать.

## Проверка работоспособности (выполнено в этом проходе)

- `cargo check --target wasm32-unknown-unknown` и `cargo build --target
  wasm32-unknown-unknown` успешно проходят (0 предупреждений).
- С помощью `wasm-bindgen --target web` сгенерированы `pkg/aruaru_web.js` /
  `pkg/aruaru_web_bg.wasm`, страница `index.html` загружена в реальном
  браузере (Chromium через Playwright), и на практике проверены следующие
  действия: переключение вкладок, выполнение SQL-запроса с отрисовкой
  офлайн-заглушки, запись в историю запросов, повторная загрузка и
  всплывающая подсказка при наведении, сочетание клавиш Ctrl+Enter,
  экспорт в CSV (с реальным срабатыванием скачивания), сводка реестра и
  получение списка зарегистрированных БД, работа вкладки «Управление
  версиями» (список веток, журнал коммитов, получение diff — включая
  офлайн-заглушку для каждого из этих запросов), отображение
  зарегистрированных сайтов на вкладке «Управление сайтами», добавление
  нового сайта, отклонение некорректного значения порта, кнопка проверки
  соединения, экспорт/импорт JSON (проверен по полному циклу туда-обратно)
  и диалог подтверждения удаления (как отмена, так и подтверждение).
  Ошибок JS в консоли не обнаружено (только ожидаемые логи о неудачном
  подключении).
- В контейнере этого прохода фактически установлены Nginx 1.24 (стандарт
  Ubuntu 24.04), Apache 2.4 и certbot; сгенерированные `scripts/gen-vhost.sh`
  конфигурации были запущены с самоподписанным сертификатом и проверены
  через `curl` (редирект HTTP→HTTPS, путь ACME-проверки, обратный прокси
  на `/graphql`); `scripts/check-tls.sh` был выполнен против реально
  запущенного HTTPS-сервера и подтвердил все три состояния — WARN/healthy/
  ERROR; конфигурации `deploy/systemd/*` проверены командой
  `systemd-analyze verify` (0 ошибок). В ходе этой проверки была
  обнаружена и исправлена реальная ошибка в шаблоне vhost для Nginx
  (директива `http2 on;` вызывает синтаксическую ошибку в Nginx 1.24).
  Фактическое получение сертификата Let's Encrypt через certbot (ACME-
  авторизация) не проверено — из-за отсутствия публичного домена и
  несовпадения ABI Python в тестовом окружении (подробности см. в
  CLAUDE.md).

## Структура

```text
aruaru-web/
├── Cargo.toml            # crate-type = ["cdylib", "rlib"], зависимости wasm-bindgen/web-sys
├── src/
│   ├── lib.rs             # точка входа, переключение вкладок, подключение обработчиков событий
│   ├── dom.rs             # общие вспомогательные функции для работы с DOM (скачивание файлов и т. д.)
│   ├── graphql.rs         # вызовы fetch к /graphql
│   ├── render.rs          # рендеринг результатов SQL и сводки реестра, экспорт в CSV
│   ├── profiles.rs        # управление сайтами (профили подключения, сохранение в localStorage, импорт/экспорт JSON)
│   ├── history.rs         # история SQL-запросов (последние 10, сохранение в localStorage)
│   └── shell.rs           # HTML-оболочка (вкладки, формы)
├── index.html             # загрузчик pkg/ + CSS
├── pkg/                   # артефакты wasm-bindgen (исключены через .gitignore, пересоздаются при сборке)
├── scripts/
│   ├── serve.sh            # запуск сервера разработки с раздачей по произвольному IP-адресу
│   ├── gen-vhost.sh         # генерация vhost для Nginx/Apache из домена/IP
│   ├── setup-tls.sh         # получение сертификата Let's Encrypt
│   ├── check-tls.sh         # проверка срока действия сертификата одного домена
│   └── check-all-tls.sh     # массовая проверка сроков действия всех зарегистрированных доменов
├── deploy/
│   ├── nginx/vhost.conf.template
│   ├── apache/vhost.conf.template
│   ├── systemd/             # полный набор таймеров автообновления (renew) и автомониторинга (monitor)
│   └── generated/           # вывод gen-vhost.sh (исключён через .gitignore)
└── CLAUDE.md
```
