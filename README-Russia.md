# aruaru-web

**«Второй KUSANAGI» — инструмент эксплуатации, который после загрузки
приложения запускает его по IP-адресу и позволяет легко автоматизировать
регистрацию домена и переход на HTTPS (Rust → WebAssembly, без фреймворков)**

Подобно «KUSANAGI» — комплекту для развёртывания ускоренных серверов
WordPress — этот инструмент эксплуатации нацелен на то, чтобы после загрузки
приложения пройти весь путь единым потоком: **запуск по IP-адресу →
упрощение регистрации домена → автоматизация HTTPS**. Он умеет автоматически
генерировать конфигурацию реверс-прокси (Nginx/Apache) для ускорения
веб-сайтов на любом бэкенд-стеке — WordPress, PHP + Laravel, Python +
FastAPI и других, — а также предоставляет экран «Управление сайтами» для
регистрации, переключения между несколькими целевыми сайтами и проверки
связи с ними. **Функций подключения к БД (базам данных) не имеет**
(осознанно вне области применения).

## Что уже реализовано

- **Экран управления сайтами**: можно зарегистрировать несколько целевых
  точек развёртывания (IP-адрес/домен/поддомен/порт/путь) для любого
  бэкенд-стека — самого aruaru-web, WordPress, Laravel, FastAPI и т. д., —
  сохранить их в `localStorage` и одним щелчком выбирать сайт и проверять
  связь с ним (аналог списка сайтов в KUSANAGI). У каждой карточки есть
  **кнопка «Проверка соединения»** (выполняет только простую проверку
  HTTP-доступности, не меняя при этом выбранный в данный момент сайт),
  проверка корректности ввода номера порта (1–65535), **экспорт/импорт в
  JSON** списка зарегистрированных сайтов (для резервного копирования и
  переноса в другой браузер) и диалог подтверждения перед удалением.
- **Запуск по IP-адресу**: `scripts/serve.sh` позволяет привязаться к
  любому IP-адресу и порту на локальной машине или VPS и раздавать сайт.
- **Генерация vhost, ускорение, автоматическая настройка HTTPS**:
  `scripts/gen-vhost.sh` генерирует конфигурацию vhost для Nginx/Apache
  (включая редирект с HTTP на HTTPS) на основе сочетания домена, IP-адреса
  и бэкенд-стека. Поддерживаются 5 стеков: `static` (статический сайт),
  `proxy` (универсальный реверс-прокси для aruaru-db, open-web-server,
  open-raid-z и подобных систем, либо для любого другого HTTP-бэкенда),
  `wordpress`, `laravel` и `fastapi`; каждый включает настройки ускорения,
  подобранные под конкретный стек, — сжатие gzip, долгосрочное кэширование
  статических ресурсов, upstream keepalive, настройку буферов FastCGI и т. д.
- **Автоматический мониторинг и обновление HTTPS (TLS)**:
  `scripts/setup-tls.sh` получает сертификат Let's Encrypt (certbot), а
  `deploy/systemd/install-systemd-units.sh` включает «автоматическое
  обновление дважды в день» (`aruaru-tls-renew.timer`) и «мониторинг
  истечения срока действия раз в день» (`aruaru-tls-monitor.timer` →
  `scripts/check-all-tls.sh`).
- **Развёртывание на VPS**: достаточно выполнить `scripts/deploy-vps.ps1`
  из Windows PowerShell, чтобы автоматизировать сборку → загрузку на VPS →
  запуск (подробности см. в разделе «Развёртывание на VPS» ниже).

## Что пока не реализовано (честные ограничения)

- **Нет функций подключения к БД (базам данных)**. Функции, зависящие от
  конкретных продуктов баз данных, такие как выполнение SQL-запросов или
  GraphQL-запросы, осознанно оставлены вне области применения и не будут
  реализованы в дальнейшем. Даже при использовании конкретного бэкенда,
  такого как aruaru-db, экран «Управление сайтами» и генерация vhost
  (`--stack=proxy`) можно использовать как **универсальный реверс-прокси и
  инструмент управления развёртыванием**, но специфичные для этой БД
  функции запросов не предоставляются.
- Аутентификация, пагинация и автоматический повтор при ошибках не
  реализованы.
- Нативный опыт приложения, как у Tauri, не предоставляется (только WASM,
  работающий в браузере).
- **Фактическое приобретение домена и регистрация DNS-записей (действия у
  регистратора) из этого репозитория не выполняются** (поскольку это
  связано с расходами и внешними сервисами). Здесь автоматизировано только
  то, что относится к уже приобретённому домену: «генерация настроек
  vhost» и «получение, мониторинг и автоматическое обновление
  TLS-сертификата»; саму регистрацию DNS пользователь выполняет у
  регистратора самостоятельно.
- Фактическое заключение договора на VPS (с провайдером аренды серверов)
  из этого репозитория также не выполняется.

## Способ сборки

Node.js, npm и TypeScript не используются. Всё делается исключительно
средствами инструментария Rust.

```bash
rustup target add wasm32-unknown-unknown        # только при первом запуске
cargo install wasm-bindgen-cli --version 0.2.126 # только при первом запуске (версия должна совпадать с указанной в Cargo.lock)

cargo build --target wasm32-unknown-unknown
wasm-bindgen --target web --no-typescript --out-dir pkg \
  target/wasm32-unknown-unknown/debug/aruaru_web.wasm

# раздать через любой статический сервер и открыть (подойдёт что угодно, например:)
python -m http.server 8080
# открыть в браузере http://localhost:8080/index.html
```

## Запуск по IP-адресу

```bash
scripts/serve.sh 0.0.0.0 8080        # слушать на всех интерфейсах
scripts/serve.sh 192.168.1.50 8080   # слушать только на указанном IP-адресе
```

После запуска можно проверить работу, **введя IP-адрес прямо в адресную
строку браузера** (например: `http://192.168.1.50:8080/index.html`). Важная
особенность — возможность проверить работоспособность только по
IP-адресу, ещё до регистрации домена.

## Развёртывание на VPS (из Windows PowerShell)

После аренды VPS-сервера достаточно выполнить `scripts/deploy-vps.ps1` из
Windows PowerShell, чтобы автоматизировать сборку → загрузку → запуск. При
совместном использовании с `open-web-server` его можно загрузить
одновременно (этот репозиторий не вмешивается во внутреннее содержимое
`open-web-server`, а лишь указывает путь для загрузки).

```powershell
# Загрузка и запуск (только aruaru-web)
.\scripts\deploy-vps.ps1 -VpsHost 203.0.113.10 -VpsUser root -StartServer

# Одновременная загрузка open-web-server (F:\open-runo\open-web-server)
.\scripts\deploy-vps.ps1 -VpsHost 203.0.113.10 -VpsUser root -StartServer `
    -OpenWebServerPath "F:\open-runo\open-web-server"
```

Внутри это эквивалентно следующим действиям (их можно выполнить и вручную):

```powershell
# 1. Сборка локально
cargo build --target wasm32-unknown-unknown
wasm-bindgen --target web --no-typescript --out-dir pkg `
    target/wasm32-unknown-unknown/debug/aruaru_web.wasm

# 2. Загрузка на VPS (клиент OpenSSH, входит по умолчанию в Windows 10 версии 1809 и новее / Windows 11)
ssh root@203.0.113.10 "mkdir -p /root/aruaru-web"
scp -r .\index.html .\pkg .\scripts .\deploy .\Cargo.toml .\src `
    root@203.0.113.10:/root/aruaru-web/

# 3. Запуск на VPS по IP-адресу
ssh root@203.0.113.10 "cd /root/aruaru-web && bash scripts/serve.sh 0.0.0.0 8080"
```

После запуска **введите IP-адрес VPS в адресную строку браузера**
(например: `http://203.0.113.10:8080/index.html`). Если нужно всегда
поддерживать локальную копию (например, `F:\open-runo\aruaru-web`) в
актуальном состоянии, достаточно выполнить `git pull` в этом репозитории:

```powershell
cd F:\open-runo\aruaru-web
git fetch origin
git pull origin <имя-ветки>
```

**Можно использовать и без загрузки**: если вы хотите попробовать
инструмент только локально, без VPS, просто запустите `scripts/serve.sh`
локально, как описано выше в разделе «Запуск по IP-адресу». С других
устройств в той же локальной сети доступ будет возможен по адресу
`http://<IP-адрес локального компьютера>:8080/`.

## Генерация vhost, ускорение, регистрация домена/поддомена

Сам этот репозиторий не занимается приобретением доменов или регистрацией
DNS-записей (это требует действий у регистратора и связано с расходами,
поэтому выполняется пользователем отдельно). Ниже описана локальная
автоматизация (аналог «добавления сайта» в KUSANAGI), позволяющая быстро
выпустить конфигурацию реверс-прокси с настройками ускорения по стекам для
уже приобретённого домена/поддомена.

```bash
# Сам aruaru-web (статический сайт)
scripts/gen-vhost.sh --stack=static aruaru.example.com 203.0.113.10

# Универсальный реверс-прокси для aruaru-db, open-web-server, open-raid-z и подобных систем, либо для любого другого бэкенда
scripts/gen-vhost.sh --stack=proxy tool.example.com 203.0.113.10 127.0.0.1:9000

# WordPress (указывается сокет/адрес PHP-FPM)
scripts/gen-vhost.sh --stack=wordpress blog.example.com 203.0.113.10 \
  unix:/run/php/php8.3-fpm.sock /var/www/blog

# Laravel (явно указывается директория public)
scripts/gen-vhost.sh --stack=laravel app.example.com 203.0.113.10 \
  unix:/run/php/php8.3-fpm.sock /var/www/app/public

# FastAPI (реверс-прокси к ASGI-серверу, с поддержкой WebSocket и потоковой передачи)
scripts/gen-vhost.sh --stack=fastapi api.example.com 203.0.113.10 127.0.0.1:8000
```

После размещения сгенерированных файлов конфигурации (в
`deploy/generated/`, исключены через `.gitignore`) в директории
конфигурации Nginx/Apache и перезагрузки сервера получите сертификат:

```bash
scripts/setup-tls.sh aruaru.example.com admin@example.com /var/www/aruaru.example.com

# включить автоматическое обновление (дважды в день) + автоматический мониторинг (раз в день, обнаружение скорого истечения срока)
sudo deploy/systemd/install-systemd-units.sh
```

Срок действия сертификатов всех зарегистрированных доменов можно в любой
момент проверить вручную с помощью `scripts/check-all-tls.sh`. Если те же
целевые точки зарегистрировать и на экране «Управление сайтами» в GUI
aruaru-web, их список и проверку соединения можно будет выполнять прямо из
браузера.

## Проверка работоспособности (выполнено в этом проходе)

- `cargo check --target wasm32-unknown-unknown` и `cargo build --target
  wasm32-unknown-unknown` оба завершились успешно (0 предупреждений).
- С помощью `wasm-bindgen --target web` сгенерированы `pkg/aruaru_web.js` /
  `pkg/aruaru_web_bg.wasm`, после чего `index.html` был загружен в реальном
  браузере (Chromium, через Playwright); были фактически выполнены и
  проверены следующие действия: отображение зарегистрированных сайтов на
  экране управления сайтами, добавление нового сайта, отклонение
  некорректного ввода порта, кнопка проверки соединения (успешно
  подтверждена доступность реально работающего HTTP-сервера), диалог
  подтверждения удаления (как отмена, так и подтверждение), экспорт в
  JSON. Ошибок JS в консоли не обнаружено.
- Были фактически установлены Nginx 1.24 (стандарт Ubuntu 24.04) и Apache
  2.4; результаты генерации для всех 5 стеков `gen-vhost.sh`
  (static/proxy/wordpress/laravel/fastapi) синтаксически проверены с
  самоподписанным сертификатом как через `nginx -t`, так и через
  `apache2ctl configtest`; для стеков static/proxy выполнен реальный запуск
  и функциональная проверка через `curl` (редирект с HTTP на HTTPS,
  раздача статического контента, ответ 502 через реверс-прокси).
- Фактическое получение сертификата Let's Encrypt через certbot
  (ACME-аутентификация), а также работа `scripts/deploy-vps.ps1` в
  реальном окружении VPS не были проверены, так как в этой сессии
  отсутствуют публичный домен, реальный VPS и среда Windows (подробности
  см. в CLAUDE.md).

## Структура

```text
aruaru-web/
├── Cargo.toml            # crate-type = ["cdylib", "rlib"], зависимости wasm-bindgen/web-sys
├── src/
│   ├── lib.rs             # точка входа, подключение обработчиков событий
│   ├── dom.rs             # общие вспомогательные функции для работы с DOM (загрузка файлов и т. д.)
│   ├── profiles.rs        # управление сайтами (профили подключения, сохранение в localStorage, проверка соединения, импорт/экспорт JSON)
│   └── shell.rs           # HTML-оболочка
├── index.html             # загрузчик, подключающий pkg/, + CSS
├── pkg/                   # артефакты wasm-bindgen (исключены через .gitignore, пересоздаются при сборке)
├── scripts/
│   ├── serve.sh            # запуск сервера разработки с раздачей по произвольному IP-адресу
│   ├── deploy-vps.ps1       # сборка, загрузка и запуск на VPS из Windows PowerShell
│   ├── gen-vhost.sh         # генерация vhost для Nginx/Apache по домену/IP/стеку
│   ├── setup-tls.sh         # получение сертификата Let's Encrypt
│   ├── check-tls.sh         # проверка срока действия сертификата для одного домена
│   └── check-all-tls.sh     # массовая проверка срока действия для всех зарегистрированных доменов
├── deploy/
│   ├── nginx/vhost-{static,proxy,wordpress,laravel,fastapi}.conf.template
│   ├── apache/vhost-{static,proxy,wordpress,laravel,fastapi}.conf.template
│   ├── systemd/             # набор таймеров автоматического обновления (renew) и мониторинга (monitor)
│   └── generated/           # результаты работы gen-vhost.sh (исключены через .gitignore)
└── CLAUDE.md
```
